# 动效与流转说明

> 更新时间：2026-04-28
> 适用范围：设计稿4 与后续前端还原

## 1. 文档用途

这份文档收敛全站的：

1. 页面流转关系
2. 面包屑与返回路径
3. 页面职责边界
4. 动效原则
5. 页面级交互反馈

目标不是做炫技说明，而是确保后续实现时：

1. 页面会动，但不喧宾夺主
2. 流程完整，不断链
3. 同类页面的交互语言统一

## 2. 全站流转总原则

### 2.1 页面流转必须闭环

所有详情页和功能页都必须满足：

1. 能从上一级中心页进入
2. 能通过面包屑清晰返回
3. 能继续进入下一步动作页

### 2.2 页面职责不能混用

1. 产品详情页负责解释成熟产品
2. 实验室详情页负责解释开发中项目
3. 心愿单页负责收集期待
4. 快来尝鲜页负责统一销售与预付验证
5. 购买页负责单商品订单承接
6. 内测报名页负责实验项目报名
7. 下载与交付中心负责后续拿货与服务

## 3. 关键流转路径

### 3.1 内容转化流

### 3.2 产品转化流

### 3.3 游戏体验流

首页 -> 游戏中心 -> 拼音大冒险详情 -> 在线轻试玩 / 心愿单 / 育儿助手 / 快来尝鲜

### 3.4 实验室转化流

首页 -> 实验室 -> 实验室详情 -> 内测报名 / 加入心愿单 / 加入社区 / 快来尝鲜

### 3.5 搜索导览流

首页搜索 -> 搜索结果页 -> 对应详情页  
404 / 搜索空结果 -> 网站地图页 -> 对应页面

## 5. 文章中心入口规则

文章中心虽然不在主导航中，但必须清晰可达：

1. 首页必须有独立入口模块
2. 昆廷笔记页必须有“进入文章中心”按钮
3. 启鸣宝宝页必须有“进入文章中心”按钮
4. 搜索结果页必须能跳转文章中心
5. 文章详情页面包屑必须能返回文章中心
6. 网站地图页必须列出文章中心

## 6. 动效总原则

### 6.1 风格基调

动效必须满足：

1. 轻量
2. 克制
3. 精致
4. 统一
5. 明确反馈

### 6.2 统一规则

1. 页面进入以淡入 + 轻位移为主
2. 卡片 hover 为轻微抬升 + 阴影或描边增强
3. 按钮 hover 为亮度、边框或胶囊高光反馈
4. 模块进入视口时采用渐入或 stagger 渐入
5. 动效时长、缓动、节奏全站统一收口

### 6.3 禁止事项

1. 粒子大爆炸
2. 全页复杂转场
3. 大面积重模糊飞入
4. 每页一套不同动画系统
5. 抢走正文与 CTA 注意力的特效

## 7. 页面级动效说明

### 7.1 首页

1. Hero 文案分层渐入
2. 主视觉拼贴可有轻微漂浮或层叠入场
3. 产品矩阵卡片错位淡入
4. 快来尝鲜横幅有轻量焦点强化
5. 互动入口卡有轻量预告感

### 7.2 内容页

#### 昆廷笔记 / 启鸣宝宝 / 文章中心 / 分类聚合

1. 标签 hover 有状态变化
2. 文章卡 hover 有明确点击反馈
3. 筛选切换有柔和过渡

#### 文章详情页

1. 正文保持稳定阅读体验
2. 文中推荐位进入视口时轻微淡入
3. 侧栏目录和推荐模块保持稳定，不做花哨运动

### 7.3 产品页

#### 产品中心

1. 产品卡片入场渐显
2. 获取体验按钮反馈更明确
3. 下载动态墙入口可有轻微热度提示

#### 产品详情页

1. 首屏整体偏稳
2. 功能块与场景块进入视口时渐入
3. 截图区可做轻滑动提示感
4. CTA、尝鲜入口、下载入口需要明显但克制的反馈

### 7.4 游戏页

#### 游戏中心

1. 游戏卡片 hover 更有活力，但不过度跳跃
2. 试玩入口更强反馈

#### 拼音大冒险详情页

1. 首屏允许轻微漂浮元素
2. 试玩按钮反馈明显
3. 教育价值与相关推荐区以稳定阅读为主

### 7.5 转化页

#### 快来尝鲜页

1. 分类切换平滑
2. 商品卡 hover 反馈清楚
3. 状态标签要一眼可识别
4. 不要用大促式夸张动画

#### 购买页

1. 动效极简
2. 支付说明与订单信息切换只做轻淡入
3. 安全感优先于炫目效果

#### 购买成功页

1. 成功状态可有轻量勾选或色块过渡
2. 下一步步骤卡顺序渐入即可

### 7.6 实验室与辅助闭环页

#### 实验室总页 / 详情页

1. 状态标签切换需要清晰
2. 时间线与版本计划区可做轻量视口渐入
3. 原型预览卡片 hover 有轻层级提升

#### 内测报名页

1. 表单 focus 态、完成态必须清晰
2. 提交按钮状态变化要明确
3. FAQ 允许折叠展开过渡

#### 下载与交付中心

1. 下载卡、交付状态卡需要清楚区分
2. 状态标签可做轻量更新反馈
3. 版本记录区适合用轻微计数或时间线过渡

#### 网站地图页

1. 分区卡 hover 高亮
2. “按目标浏览”入口反馈要明显
3. 页面整体以导览清晰度优先

### 7.7 互动页

#### 下载动态墙

1. 图标由上向下掉落
2. 落地时有轻微弹性反馈
3. 统计数字允许轻微更新动画
4. 页面保持品牌互动装置感，而不是后台监控感

#### 在线轻试玩

1. 开始按钮状态变化明确
2. 分数和状态区有微动画
3. 失败时可以有轻微震动或色彩提示
4. 不使用复杂粒子和强爆炸反馈

#### 心愿单

1. 收藏成功要有反馈
2. 状态切换可以轻微缩放或淡入
3. 愿望数量、状态标签更新可有微动画

## 8. 状态设计要求

全站需要至少考虑下列状态：

1. 默认状态
2. hover / focus 状态
3. 已选中状态
4. 加载或等待状态
5. 空状态
6. 成功状态
7. 失败或异常状态

建议：

1. 全站等待态优先骨架屏或 shimmer
2. 不把传统 loading 圈作为主要方案
3. 空状态要有回流入口，而不是只写“暂无内容”

## 10. 后续实现时的使用方式

后续前端还原时，优先按这份文档判断：

1. 页面从哪里进、往哪里走
2. 某个按钮应该承接到哪类页面
3. 某类页面应该稳、还是应该更有互动感
4. 某个页面的动效是否已经超过“克制”的边界
