# 后台使用文档

> 更新时间：2026-05-04
> 对应版本：第一版最小可用后台（MVP）

## 1. 文档目的

这份文档说明 3 件事：

1. 目前后台做到了什么
2. 怎么启动和使用
3. 后续应该怎样从 MVP 继续演进到正式后台

## 2. 与《数据说明与后台规划》的关系

本次开发严格按 [数据说明与后台规划](./数据说明与后台规划.md) 的一期顺序执行，但只先落第一步。

规划文档建议的起步顺序是：

1. 先建 `projects`、`articles`、`content_categories`、`content_tags`
2. 再建报名、线索、心愿单
3. 再建订单与下载交付
4. 最后做埋点与运营统计

这次实际实现的是其中最小、最容易形成闭环的一段：

1. `content_categories` 的最小映射：`columns`
2. `content_tags`
3. `articles`
4. `admin_users` 的最小登录能力

原因是：

1. 当前前端已经有完整文章中心和专栏页
2. 当前静态内容最集中地落在文章数据里
3. 文章管理最适合作为后台第一批真实数据源

## 3. 本次已实现能力

已新增目录：`backend`

当前已实现：

1. 一个轻量级 `Python + FastAPI` 后台服务
2. 一个可直接访问的后台页面 `http://localhost:4100/admin`
3. 管理员登录
4. 栏目读取
5. 标签读取
6. 文章列表读取
7. 文章详情读取
8. 文章新增、编辑、删除
9. 全站配置管理
10. 页面配置管理
11. SQLite 数据持久化
12. `hope` 前端主要模拟数据已收敛入库
13. 文章 / 项目 / 商品 / 配置的基础 CRUD 已可用

## 4. 启动方式

在项目根目录下执行：

```bash
cd backend
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 4100
```

默认启动地址：

- 后台页面：`http://localhost:4100/admin`
- 健康检查：`http://localhost:4100/health`

默认管理员账号：

- 用户名：`admin`
- 密码：`admin123`

## 5. 后台页面怎么用

进入后台页面后：

1. 先用默认账号登录
2. 可在“文章管理”里维护文章内容
3. 可在“全站配置”里维护站点通用字段
4. 可在“页面配置”里维护页面级 JSON 配置
5. 首次启动会把 `backend/data/content.json` 导入 SQLite
6. 后续数据默认写入 `backend/data/app.db`
7. 列表里的删除按钮会直接删除对应数据

当前页面是 MVP 级管理台，重点是验证后台闭环，不是最终管理系统 UI。

## 7.1 已收敛入库的数据

当前已经从 `hope/src/data/` 收敛进数据库的内容包括：

1. 文章、专栏、标签
2. 产品数据
3. 实验室数据
4. 尝鲜商品数据
5. 站点基础信息、导航、页脚、社交链接
6. 主要页面的基础配置 JSON

这意味着 `hope` 内最核心的模拟数据已经不再只存在前端文件里。

## 7. 当前版本的边界

这一版故意没有做下面这些内容：

1. 保持 SQLite 生产配置与文件备份
2. 文件上传
3. 多角色权限
4. 项目管理
5. 报名、线索、心愿单、订单、统计
6. 迁移脚本与发布流程

不是因为这些不重要，而是因为第一版应该先证明后台链路能跑通。

## 8. 推荐下一步

如果继续开发后台，建议按这个顺序推进：

1. 先把前端文章接口切到 `backend` 的读取接口
2. 把 `projects` 和 `project_versions` 接进后台
3. 再补 `beta_applications`、`community_leads`、`wishlist_items`
4. 通过 `SQLITE_DB_PATH` 固定生产数据库文件路径
5. 补上迁移与生产部署脚本
