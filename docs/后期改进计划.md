# 后期改进计划

> 更新时间：2026-04-28
> 当前状态：设计稿完成，等待进入前端高保真还原与内容补齐阶段

## 1. 文档用途

这份文档只记录“后续还要继续做什么”，不重复基础定位与页面树。

所有改进项分为：

1. 上线前高优先级
2. 设计还原与体验增强
3. 内容与 SEO
4. 转化与信任
5. 数据与技术升级

## 2. 第一优先级：先把核心页面做成成品

当前最重要的问题已经不是“有没有页面”，而是“页面还原后能不能达到设计稿成品感”。

因此第一优先级不是继续补页，而是优先打磨：

1. 首页
2. 产品中心页
3. 文章中心页
4. 昆廷笔记页
5. 启鸣宝宝页
6. 三个产品详情页
7. 快来尝鲜页
8. 实验室详情页

验收标准：

1. 明显脱离框图感
2. 模块层级稳定
3. 有真实网页成品感
4. 能直接作为展示页使用

## 3. 第二优先级：补齐真实内容与素材

### 3.1 产品内容

1. 补齐 3 个 App 的真实卖点
2. 补齐 3 个 App 的真实截图
3. 明确下载状态、体验方式和版本信息
4. 为下载与交付中心补真实交付内容

### 3.2 游戏内容

1. 补齐重点游戏玩法说明
2. 补齐游戏截图与体验链路
3. 为在线轻试玩补真实规则、状态和反馈

### 3.3 信任素材

1. 私域二维码
2. 联系方式
3. 用户反馈截图
4. 使用场景图
5. 购买后交付示意图

## 4. 第三优先级：前端高保真还原

### 4.1 视觉系统统一

1. 统一标题层级
2. 统一按钮系统
3. 统一卡片系统
4. 统一边框、圆角、阴影和高光
5. 统一标签、状态和筛选样式
6. 统一底部承接模块

### 4.2 页面还原顺序

建议按下面顺序推进：

1. 首页
2. 产品中心
3. 文章中心
4. 昆廷笔记
5. 启鸣宝宝
6. 产品详情页
7. 文章详情页
8. 游戏中心与拼音大冒险详情页
9. 快来尝鲜 / 购买 / 购买成功
10. 实验室 / 内测报名
11. 下载与交付中心
12. 下载动态墙 / 在线轻试玩 / 心愿单
13. 搜索页 / 网站地图 / 404 / 隐私页

## 5. 第四优先级：转化链路增强

### 5.1 快来尝鲜

1. 补齐商品真实文案
2. 区分可立即购买、预付验证、限量尝鲜、首发测试
3. 补交付方式、FAQ、权益说明

### 5.2 购买链路

1. 细化套餐与权益结构
2. 补付款后步骤说明
3. 打通购买成功页与下载与交付中心

### 5.3 实验室链路

1. 明确哪些项目只收集心愿
2. 明确哪些项目开放内测
3. 明确哪些项目可以导向快来尝鲜

## 6. 内容与 SEO 改进

### 6.1 SEO 内容补齐

1. 补 3 到 5 篇真实 SEO 文章
2. 每个 App 至少挂 1 篇教程或场景文章
3. 补 1 到 2 个专题聚合页

推荐专题：

1. AI 提效工具合集
2. 幼小衔接工具合集
3. 家长启蒙资源页
4. 教育游戏专题页

### 6.2 搜索能力迭代

建议升级顺序：

1. 热门词跳转
2. 静态索引搜索
3. 全文搜索

可选方案：

1. JSON 索引搜索
2. Pagefind
3. Algolia

## 7. 互动功能增强

### 7.1 下载动态墙

1. 不同 App / 游戏使用不同掉落频率
2. 增加分类切换与标签显示
3. 接入真实下载、预约或安装数据
4. 作为首页活动位或阶段性热度页使用

### 7.2 在线轻试玩

1. 增加分数记录
2. 做更完整的开始、进行、失败、重开反馈
3. 节日活动轮换不同小游戏
4. 继续拓展更多小游戏原型

### 7.3 心愿单

1. 数量统计
2. 项目热度排序
3. 上线提醒
4. 私域通知联动
5. 后台查看最受期待项目

## 8. 主题系统与后台可配置能力

后续建议将主题变量系统化，为活动期和阶段调整做准备。

推荐主题：

1. 明亮科技版
2. 温暖陪伴版
3. 实验室未来版
4. 节日活动版

后台能力建议：

1. 主题切换选择器
2. 主题预览缩略图
3. 一键应用全站
4. 局部栏目覆盖
5. 保存为当前主题

## 9. 数据与埋点

建议尽早建立基础埋点，优先记录：

1. 下载点击
2. 尝鲜点击
3. 支付意向点击
4. 私域点击
5. 搜索词
6. 产品互导点击
7. 内测报名提交
8. 心愿单加入与切换状态

## 10. 技术路线建议

### 10.1 当前阶段

1. 优先保持现有结构稳定
2. 先完成设计稿级前端还原
3. 再逐步补搜索、埋点、内容与真实数据

### 10.2 后续可升级方向

1. 继续保持静态结构并增强脚本能力
2. 完善 Astro 化实现
3. 当内容、搜索与数据复杂度上升后，再考虑更重的应用层方案

## 11. 执行原则

1. 缺素材时，优先补素材，不让页面长期停在占位状态
2. 缺内容时，优先补最影响转化的真实内容
3. 不为追求页面数量牺牲质感
4. 先打磨样板页，再扩散到全站
5. 所有改进都要围绕“更接近设计稿成品感”和“更接近真实可用网站”展开
